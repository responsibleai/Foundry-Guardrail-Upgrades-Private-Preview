# Contributing

This project welcomes contributions and suggestions. Most contributions require you to agree to a Contributor License Agreement (CLA) declaring that you have the right to, and actually do, grant us the rights to use your contribution. For details, visit [Contributor License Agreements](https://cla.opensource.microsoft.com).

When you submit a pull request, a CLA bot automatically determines whether you need to provide a CLA and decorates the PR appropriately (for example, with a status check or comment). Follow the instructions provided by the bot. You only need to do this once across all repos using our CLA.

## Code of conduct

This project has adopted the [Microsoft Open Source Code of Conduct](https://opensource.microsoft.com/codeofconduct/). For more information, see the [Code of Conduct FAQ](https://opensource.microsoft.com/codeofconduct/faq/) or contact [opencode@microsoft.com](mailto:opencode@microsoft.com) with any additional questions or comments.

## Report an issue

If you find a mistake in the documentation, such as an inaccurate step, a broken link, or a missing detail, [open an issue](https://github.com/responsibleai/Foundry-Guardrail-Upgrades-Private-Preview/issues/new). Search [existing issues](https://github.com/responsibleai/Foundry-Guardrail-Upgrades-Private-Preview/issues) first to avoid duplicates.

To help us act on it quickly, include:

- The article and section.
- What's wrong or missing, and what you expected.
- For product behavior that doesn't match the docs, the steps to reproduce it and what you observed.

Don't report security vulnerabilities through GitHub issues. See [SECURITY.md](SECURITY.md).

## Submit a pull request

1. Search the repository's [pull requests](https://github.com/responsibleai/Foundry-Guardrail-Upgrades-Private-Preview/pulls) to avoid duplicating effort.
1. Fork the repository, and create a branch for your change.
1. Make your changes. Follow the style of the existing articles, which align with the [Microsoft Writing Style Guide](https://learn.microsoft.com/style-guide/welcome/).
1. Commit your changes with a descriptive commit message, and push the branch to your fork.
1. Open a pull request against the `main` branch, and describe what you changed and why.
1. If reviewers request changes, update your branch. The pull request updates automatically.

For larger changes, such as a new article, open an issue to discuss the proposal before you start.
